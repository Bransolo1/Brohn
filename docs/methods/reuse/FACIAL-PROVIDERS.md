# Facial-expression reuse for Brohn

Checked 2026-09-08. Recommendation: retain facial-expression timelines and condition comparisons. Start with local MediaPipe movement features; add an explicitly configured Py-Feat modular detector for AU and expression scores. For supported commercial extraction, shortlist Affectiva's local SDK and batch API. A laboratory already using FaceReader can supply the fastest licensed integration. Hume's facial service needs renewed availability confirmation.

Keep native model labels, valid-data coverage, stimulus alignment and reported affect visible. Expression scores describe a model's interpretation of facial appearance; questionnaire answers remain the participant's reported experience. Useful first analyses are per-stimulus AU/expression trajectories, baseline contrasts, paired condition differences and associations with liking. Avoid converting frames into independent participants.

## Timing and missingness contract

FaceReader 9 defines **10,000,000 ticks per second**. Video ticks refer to video time; camera ticks count from `AnalysisStartTime`. Retain raw decimal strings, source-clock identity and typed arrays. The published example `3697600000` is exactly `369.76` seconds. The API note reviewed is version 9, despite newer version-10 product documentation; require a version-10 sample before asserting wire compatibility. [API specification](https://noldus.com/shared/resources/book/noldus-product-documentation/chapter/facereader/page/facereader-9-api-overview-and-usage)

FaceReader 10 detailed logs use `FIND_FAILED`, `FIT_FAILED` and `MISSING` for detection failure, modeling failure and skipped camera frames. Tokens can be configured. Export resampling can interpolate or average. These log semantics do not establish their exact XML placement. Preserve a legitimate zero score; keep missing/null/absent fields distinct and unknown tokens unmapped. [Detailed-log specification](https://noldus.com/shared/resources/book/noldus-product-documentation/chapter/facereader/page/facereader-10-detailed-log)

Affectiva's product-level output descriptions are insufficient to assume identical units across SDK, iMotions export and HTTP API. Acquire one versioned reference response with missing-face and multi-face cases. Never infer acquisition timestamps from inference completion or frame number alone.

## Public method evidence

- **MediaPipe:** the authors' [Blendshapes GHUM paper](https://arxiv.org/abs/2309.05782) supports an established on-device movement-estimation method. It does not qualify Brohn's emotion or screen-gaze interpretation.
- **Py-Feat:** [Cheong et al. (2023)](https://link.springer.com/article/10.1007/s42761-023-00191-4) benchmarked AU estimates against DISFA+ annotations and expression classification on AffectNet, including lighting/occlusion experiments. Those results concern the tested implementations; current [per-release benchmark records](https://py-feat.org/benchmarks/accuracy/) provide a closer version trail.
- **AFFDEX:** the [AFFDEX 2.0 methods paper](https://arxiv.org/abs/2202.12059) and [2026 vendor benchmark](https://imotions.com/wp-content/uploads/2026/04/AFFDEX2-vs-Open-Source-Toolkits.pdf) provide reusable model evidence. The latter evaluates 13 AUs on 7,805 videos and is vendor-authored. [Independent earlier testing](https://link.springer.com/article/10.3758/s13428-017-0996-1) found expression/database-dependent performance; it does not test today's binary.
- **FaceReader:** its [version-10 methodology](https://noldus.com/shared/resources/book/noldus-product-documentation/chapter/facereader/page/facereader-10-how-does-facereader-work) describes ADFES/WSEFEP validation. [AU validation white paper](https://noldus.com/download/document/white-paper-facereader-action-unit-validation) is separate evidence. Preserve exact model/version correspondence.
