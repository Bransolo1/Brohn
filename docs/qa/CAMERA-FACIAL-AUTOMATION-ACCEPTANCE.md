# Automatic camera facial processing acceptance

Status, 24 September 2026: this optional workflow is implemented and qualified by joined browser evidence, 13 loaded integration checks and six independent native-reference checks. Work is paused at the user's request after this evidence/documentation closure. This is not whole-platform or scientific validation.

## Delivered behaviour

Researchers can choose the named local facial profile in Plan > Camera and microphone, set its exact recording-relative window, frame stride and supported interval, and inspect the participant notice before release. The participant's existing camera checkbox expressly covers recording and the displayed local facial processing. Its original positive or negative decision and complete policy digest are retained with the frozen study/protocol and recording.

Completed eligible recordings automatically create one native analysis job using the original dataset revision and exact settings. Completion and assembly can arrive in either order. A missing optional environment fails the processing job while preserving the original recording and participant completion receipt. Retry keeps the same source and permission authority. Older recording/geometry permissions remain distinct from separately documented later manual facial permission.

Source authority is checked at queue, supervised input, pre-child guards, publication, report access and downloads. Guards cover original chunks, observations, complete assembly evidence and source video. Received withdrawal remains binding even if the final participant receipt was lost. Original incomplete, withdrawn or researcher-resolved sessions cannot silently acquire raw completion for this automatic route.

## Reproduction

Use the restored R library and `LC_ALL=C`, the configured native publication guard, pinned optional facial Python/models/FFmpeg, and a fresh evidence directory. Existing directories are not deleted or silently reused for a new fixture.

```powershell
& ../../work/native-r/bin/Rscript.exe tests/platform-camera-automatic.R ../../work/test-runs/brohn-camera-automatic-NEW
& ../../work/native-r/bin/Rscript.exe tests/fixtures/researcher-camera-facial.R setup ../../work/test-runs/brohn-camera-facial-browser-NEW
& 'C:/Users/User/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe' tests/researcher-camera-facial.mjs ../../work/test-runs/brohn-camera-facial-browser-NEW
& ../../work/tooling/facial-au-venv/Scripts/python.exe tests/camera-facial-native-reference.py ../../work/test-runs/brohn-camera-facial-browser-NEW/browser-TIMESTAMP
```

The browser folder must already exist before setup. The harness handles only its own services and stops them cleanly. Native reference inference runs after the browser's native job is terminal. See the [camera authority contract](../architecture/CAMERA-ANALYSIS-CONTRACT.md) and [optional facial setup](../methods/FACIAL-AU-NATIVE-PROFILE.md).

For the retained joined continuation, `tests/researcher-camera-facial-finish.mjs` takes the original workspace and completed parent browser folder. It intentionally pins the documented source delta and reuses the existing report. It is an evidence continuation, not a standalone default QA catalog test. All owned researcher/participant/worker/browser processes and the independent native process are terminal.
