## State and authority boundaries

Tickets bind the selected report, project, audio window and exact saved review.
Close, report navigation and superseding actions fence old acknowledgements and
deferred input updates. Verification checks both exact DOM controls and actual
R input state. Real later edits retain the existing warning and guarded-URL
invalidation. Failed access leaves a visible recoverable message and re-enables
the native fieldset; no stale exports are shown.

Focus and scrolling are scoped to the current opening ticket. Deliberate focus
movement, wheel or touch scrolling yields ownership. A later verification phase
may continue when exact controls match without stealing that user's focus or
deadlocking offscreen. A removed control returning focus to the body does not
restore ownership. All automatic scrolling is instant, including reduced-motion
use. The client acknowledgement is a rendering handshake, never authorization.

The Shiny component uses real saved sources and fresh project guards, but
deliberately bypasses one successful native transition solely for state
inspection. Fake-DOM tests do not prove real browser paint. Their limits are
covered by the actual connected phases rather than hidden in combined totals.
The retained `evidence-02/initial-paint-failure.json` documents a fake fixture
that entered verification without first establishing its preparation focus
owner. Its setup was corrected; the product fence was preserved.
