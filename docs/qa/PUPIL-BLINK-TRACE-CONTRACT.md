# Complete pupil and source-labelled blink traces

20 September 2026. **Design contract, following independent source and primary-literature review.** Implementation and measured software evidence are recorded separately in [Pupil and source-labelled blink trace acceptance](PUPIL-BLINK-TRACE-ACCEPTANCE.md). No physical eye tracker is available; these software tests cannot qualify acquisition, pupil calibration, blink detection or physiological interpretation.

## Recommendation

Save complete, typed pupil and externally supplied blink samples during a new original sampled-gaze analysis. Add one exposure-specific trace beside the existing gaze report, using the same frozen source, mapping, study and already-computed baseline. Preserve the original summary arithmetic. Correct the separately versioned blink boundary flags described below. Existing reports remain immutable; a missing trace requires a new analysis of the explicitly selected original source revision, never reconstruction from a summary mean.

Start with one mapped pupil column, its declared eye/source description and unit, and/or one mapped external blink-label column. Do not introduce binocular averaging, filtering, blink detection, reconstruction, interpolation or a new baseline algorithm in this addition. Those would need separate methods and reference evidence.

## Primary academic basis

The full publisher text of both requested articles was accessible and read on 20 September 2026; this review did not rely on an inaccessible transcript or abstract alone.

- Mathôt, Fabius, Van Heusden and Van der Stigchel (2018) show that baseline distortions can affect corrected results, especially division by a small baseline. They recommend identifying invalid data before correction, subtractive correction, and visual comparison of original and corrected traces. Their discussion distinguishes missing zeros from real pupil measurements and cautions against implausibly rapid responses and small contaminated baselines. This supports showing raw values, exclusions, the actual baseline and its limitations together; it does not validate Brohn's current thresholds. [Safe and sensible preprocessing and baseline correction of pupil-size data](https://link.springer.com/article/10.3758/s13428-017-1007-2).
- Kret and Sjak-Shie (2019; first published online in 2018) describe explicit raw-data preparation, invalid-sample rejection, optional interpolation/filtering and segment analysis, with visual inspection of intermediate results. Their settings depend on recording characteristics, and their pipeline does not label blinks. This supports preserving declared validity and separate source labels, showing gaps, and avoiding universal artifact thresholds. The proposed Brohn trace exposes its existing unsmoothed observations; it does not claim to implement their preprocessing pipeline. [Preprocessing pupil size data: Guidelines and code](https://link.springer.com/article/10.3758/s13428-018-1075-y).

The implementation requirements below are this product's proposed contracts, not additional recommendations attributed to those papers. Luminance, gaze geometry, eye/source choice, units and study design still constrain interpretation. A supported baseline denominator is not proof that a baseline is physiologically suitable.

## Narrow blink policy correction

Keep the existing `brohn-adjacent-ray-ivt/0.1.0-draft` detector identifier and I-VT arithmetic. Add explicit `parameters.blink_boundary_policy = "source-labelled-blink-boundaries/1.1"` and bind it into the new artifact provenance. A separate trace profile, `gaze-pupil-source-trace/1.0`, identifies the new retained-data route.

Continue to produce passive-viewing source-labelled events with the existing first/last labelled timestamps, sample counts and observed durations. A new onset is unobserved if its first positive label is at the record boundary, follows an unsupported gap, **or follows a still-positive label outside passive viewing**. Apply the symmetric rule to the last positive label and its following sample. Save reason flags separately, including phase clipping. A preceding/following explicit false label within supported cadence brackets the source-labelled transition; it is not an exact physiological eyelid onset or offset.

Do not extend an event into another phase or invent a duration beyond observed first/last positive samples. A single positive sample has zero observed span and must remain a visible tick with boundary/support information. Baseline-only and response-only labels remain in the complete trace but do not create passive blink events.

Historical reports without this policy retain their original flags and bytes. Their new view must visibly state that legacy blink-boundary flags did not account for phase clipping; a false legacy flag must not be described as proof of a fully observed blink. A fresh analysis may produce the corrected policy and trace in a separate report. No view silently rewrites a historical result.

## Complete retained-data contract

Use the existing typed NDJSON, independent verification and immutable publication machinery where possible. A `physiology-series` container is suitable for storage; its explicit `trace_profile` and dedicated gaze adapter define the measurement semantics. Generic line-preview paths must reject this profile until they understand its separate pupil, phase and blink masks. The exact-values route may read its numeric columns because it retains all source rows and typed support.

One table represents one exact participant/session/exposure/stimulus and the mapped pupil source. Retain every accepted input row, including baseline, passive, response/other phases, invalid pupil samples and groups with no passive summary. Preserve source order; never sort, merge exposures or infer that skipped global source indices are elapsed time. Explicitly distinguish global source row (one-based CSV data row) from zero-based table row. The full table and manifest must reconcile with the original source denominator.

Required per-row fields are:

- Original source row, original time text/unit, parsed analysis time in milliseconds, and an explicitly declared seconds coordinate for shared typed tooling. Preserve the original analysis-time value as well as the converted coordinate; do not claim additional timing precision or synchronization.
- Source phase and identity; whether the row lies in the declared baseline or passive exposure; pupil numeric input (nullable), original input text, declared measurement unit and source/eye description.
- Original pupil-valid and gaze-valid labels, nullable when unmapped; explicit source blink label, nullable when unmapped; left/right availability labels where mapped. Preserve the original supplied booleans separately from recipe eligibility.
- Finite/positive pupil tests and effective pupil eligibility, with overlapping reasons rather than one lossy status. A finite zero or negative value remains an original measurement field but is excluded by the existing pupil recipe. Missing numeric values remain null; they never become zero.
- Eligibility and exact duration of the following adjacent interval for the pupil summary and baseline mean. The terminal row has no following interval or invented duration. Include separate gap/phase/invalid-endpoint reasons. A lone valid sample is distinct from supported interval time.
- Pupil minus the saved baseline mean only where the declared correction applies and the baseline is eligible; otherwise null with a reason. Preserve the raw numeric pupil column. Distinguish arithmetic sample correction from membership in the summary's duration-weighted denominator; an isolated sample cannot gain interval support merely because subtraction is possible.

Resolved per-table support must include actual exposure and baseline bounds; original boundary text and source columns; baseline phase, requested minimum duration/coverage and rationale; observed baseline duration/coverage and stored mean/status; source pupil and blink provenance; gap policy; no-smoothing/no-interpolation statement; total rows and the exact relevant sample/interval counts. Nonpositive values, labelled blinks and invalid-source flags may overlap, so reason counts need not add to a unique excluded total.

The existing `eligible` baseline status means its declared duration/coverage criteria were met. Display that meaning explicitly. It does not establish plausible baseline amplitude, artifact-free baseline, or a validated cognitive response. A failed or absent baseline leaves raw observations visible and corrected values unavailable. No tiny-positive-value rejection threshold or physiological range is introduced by this trace addition.

Existing source-labelled passive blink events may be retained in a matching events artifact with source first/last rows and policy/reason fields. If added, its provenance hash must match the series artifact. The complete source-label column remains authoritative for inspecting labels outside passive viewing; missing pupil samples, missing gaze or unavailable eyes never create blink labels.

## Researcher view and acceptance

Within the existing exact exposure selector, show original pupil observations and corrected pupil observations on aligned time axes, plus an externally supplied blink-label strip when available. Clearly name the declared unit, pupil source/eye, baseline status and viewing phase. Show the baseline window and mean without implying the entire declared window was observed. Raw invalid finite values remain inspectable as distinct, unconnected observations; zero is visible as source data rather than a valid pupil. Use actual saved points only.

Line paths must break at unsupported timestamp gaps, phase changes, invalid endpoints and exposure/source boundaries. No smoothing or interpolation is introduced by plotting. If display reduction is necessary, retain observed first/last/min/max within each separately supported fragment and disclose the reduction and exact denominator. A selected-range/full-data download must retain every row, its flags and source association. The blink strip shows source labels and their unknown boundaries; it does not imply a newly detected event or physical closure duration.

The accepted implementation route uses all selected rows up to 5,000, and explicitly refuses larger chart windows rather than reducing their points. A chart SVG download must preserve the displayed source masks, units and legend, with exact report/artifact/source identity, origin, selected bounds and baseline support embedded as XML-safe metadata. Display coordinates can be rounded for SVG geometry; native selected values remain in the paired exact JSON and complete typed artifact. Changing the range, exposure or report must revoke prior download links. The horizontal numerical table must be a named keyboard-focusable region.
