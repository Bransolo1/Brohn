24 September 2026: domain/Shiny and connected researcher/participant acceptance
passed. This is evidence of preserved assignment and exact source review, not

## Researcher flow and authority

Collect keeps a short, collapsed Participant code entry on each released study.
Its review distinguishes preserved code from explicitly unknown historic code.
Review exposes the same separate record from an exact assigned protocol, and
returns to that protocol. Collection closure and finalized History expose the
release's record and return to the same collection review.

A native report with direct `provenance.runs` can review its exact original
session references, 40 per page, then inspect one code assignment. There is no
inferred execution link from an imported trial summary, participant alias or
equal score. Source membership, report revision/hash, study/project ownership,
release/design agreement and the current bound UI context are checked. The view
does not walk a whole study's session history or verify all code files on each
render.

`Download code manifest JSON` returns the original canonical manifest. A separate
`Download code provenance JSON` retains release/session and optional report
binding, preservation status and interpretation. Historic unknown sources offer
the latter record but no invented manifest. The files contain no enrollment or
run capability, participant alias, browser client ID or response journal.

The scientific protocol, received events, original report and finalized
collection inventory are not modified. Normal `brohn_run` metadata retains its
existing shape; code is obtained through the explicit separate runtime reader.
Assigned code does not prove browser execution, physical timing, scientific
validity or a completely preserved operating environment. Advanced details and
the evidence export explain that this view verifies manifest/assignment identity;
individual file bytes are checked when served and during backup.
