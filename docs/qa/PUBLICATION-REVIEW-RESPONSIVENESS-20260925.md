# Saved-review responsiveness and feedback checkpoint

25 September 2026. Continuing from published `0b7bf381208fcc08b1b503c9de2b486332fe1587`
on `Bransolo1/Brohn/main`. The full build remains active and unfinished. This
checkpoint improves two saved-review routes; it does not complete the platform.

## Delivered behavior

Saved-media reopening avoids repeated complete source reconstruction within a
single immediate call. Task evidence and plots reuse bounded canonical digests
while still reading and replaying the complete original journal. Neither route
caches permissions, source records, native file verification or replay decisions.
Fresh authority and original-source checks still govern opening and downloads.
Scientific scores, mapping, report bodies and complete exports remain unchanged.

Both routes show a specific preparation message before expensive source reads.
The current message receives focus and is revealed in the phone viewport before
its two-animation-frame acknowledgement permits source work. On completion, the
matching heading receives focus only while the request still owns it. Deliberate
keyboard, wheel or touch movement yields focus; stale tickets and navigation
cannot reclaim it. Scrolling is instant. Source refusal is visible and recoverable.
Media cursor restoration no longer produces a misleading manual-edit warning;
genuine later edits still invalidate old source URLs.

## What the measured improvement means

In a controlled same-process media comparison, native opening fell from
6.05/6.12 seconds to 2.92/2.83 seconds; terminal verification fell from
2.14/2.19 seconds to 1.06/1.14 seconds. These are function timings, not the
whole UI. Final mobile media progress was focused in view at 0.944/1.078
seconds, with result headings at 13.423/13.603 seconds before/after restart.
An image served separately can still be loading when its result heading appears.
The focus screenshot does not replace the independent PNG/source export oracle.

The task comparison measured first complete browser source preparation at
15.11 seconds before and 13.10 seconds after, and corrected repeated preparation
at 15.82 versus 8.27 seconds. The discarded 77 ms baseline timing matched stale
controls and is explicitly excluded. Final combined-source task pending states
appeared at 32.7-130.3 ms; first full readiness took 11.567 seconds and repeated
reads 7.876/7.800 seconds. Those later observations are a distinct source phase,
not another controlled percentage comparison.

Source work is still synchronous after its painted acknowledgement. These
checks do not establish nonblocking execution, arbitrary-load capacity or
concurrent responsiveness. Complete source opening remains several seconds and
is still a product performance gap. The narrower keyboard routes, automated
accessibility scans and inspected screenshots do not establish whole-platform
human usability or support for every assistive technology.
