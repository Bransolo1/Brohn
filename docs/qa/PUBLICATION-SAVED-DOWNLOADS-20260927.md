## Contract and scope

`brohn_http_identity_response(existing_httpResponse)` runs after the caller's existing source/token/current-reader checks. It preserves status, media type, exact content and unrelated headers. Full retained files keep `owned=FALSE` and stream through httpuv; no eager file copy or scientific analysis is added. Raw bytes and byte-stable UTF-8/ASCII text are supported. Unsupported encodings, partial/range response shapes, transfer coding, owned files, bodyless statuses and malformed lengths fail closed within the existing refusal boundary. The finalizer does not interpret Range request headers.

The response's dedicated header class formats Shiny's later numeric Content-Length assignment as decimal digits. One Brohn-specific S3 registry entry enables private source loading; base/Shiny functions and global formatting options remain unchanged. File metadata is not an authority check or native lock: the original caller guards still provide those protections.

This adoption excludes the already qualified report-package helper, Shiny-generated downloadHandlers, participant/collection routes, arbitrary static endpoints, partial/range responses and compressed representations. It makes no new device/scientific, large-file throughput or concurrent-mutation claim.
