## Exact scope

The procedure is `sciat-brohn-response-window-im100/1.0`, an explicitly named
Brohn adaptation. Three roles, E/I keys, 24/72/24/72 trials, opposite allocation
orders, first-response semantics, a 1500 ms inclusive event-timestamp deadline,
150/500 ms response/omission feedback and a 250 ms blank remain fixed. This
acceptance does not establish original-2006 or vendor equivalence, physical
timing qualification, stimulus validity or individual preference interpretation.

The connected journey starts in an empty isolated library and authors original
fictional Aster materials through the researcher UI. It includes explicit
liking, design template/clone/portable import, a sample release, four complete
192-trial participant administrations (768 trials), a separate interrupted refresh, an
actual received request with its acknowledgement lost, offline local event
retention, native background analysis, immutable report/plot downloads, native
trial/registry export, explicitly declared-summary reimport, reviewed two-person
aggregation and restart/reopen. All inputs are automated synthetic software QA.

## Interpretation limits

The result is an implemented, replay-validated and independently scored named
Brohn adaptation. It is not labelled equivalent to the original 2006 procedure,
Millisecond/Inquisit, an arbitrary SC-IAT or a validated psychological diagnostic.
The controls/rationale and materials language are explicit; category pairing is
not a separate control-product or causal comparison. Raw first response, omitted
response, retained scoring support and explicit liking remain distinct.

Browser automation establishes software behavior and stored-event consistency.
It does not measure physical display/key latency, real participant behavior or
construct validity. Automated accessibility scans and inspected viewports do not
replace a complete assistive-technology or human usability study. No real human
participant or private research dataset was used.
