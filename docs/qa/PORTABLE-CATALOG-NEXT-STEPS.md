# Portable QA catalog: next steps

24 September 2026. Read-only prioritization after the [portable connected smoke](CONNECTED-PORTABLE-SMOKE-ACCEPTANCE.md). No catalog suite was run for this audit, and no existing QA/runtime code was changed. These are source-inspection findings, not fresh execution failures.

[run-checks.R](../../scripts/run-checks.R) already resolves its checkout independently of the caller, runs allowlisted tests in child processes and accepts an external evidence directory. It currently accepts `--suite`, `--test` and `--output`, and requires runtime environment setup before execution. The next shared change should be a configuration-aware launcher using [local-configuration.ps1](../../scripts/local-configuration.ps1), plus explicit prerequisites/evidence metadata in [qa-catalog.json](../../scripts/qa-catalog.json). Reuse the connected smoke's runtime isolation and protected-workspace rules; do not open the configuration's research workspace.

## Three priority groups

1. **Domain core: study storage, delivery and imported-task publication.** [platform-store.R](../../tests/platform-store.R) lines 3-4, [platform-delivery.R](../../tests/platform-delivery.R) line 4 and [platform-run-evidence.R](../../tests/platform-run-evidence.R) line 4 prepend developer `../../work` R libraries. [platform-task-import-platform.R](../../tests/platform-task-import-platform.R) line 9 requires `../../work/test-runs` for retained evidence. Pass the verified library and a new per-test evidence directory explicitly, so contributors can exercise the core data/participant path from another checkout. Do not describe the whole domain suite as core-only: [platform-methods.R](../../tests/platform-methods.R) line 75 requires an external `implicitMeasures` reference library, while [platform-gaze.R](../../tests/platform-gaze.R) line 145 requires the pinned `saccades` comparator. Give reference checks explicit profiles and retain visible coverage status. [MaxDiff's upstream reference](../../tests/platform-maxdiff.R) is conditional; absence can reduce coverage without failing the test.

2. **Operations integrity: restart, backup and protected publication.** [platform-backup.R](../../tests/platform-backup.R) line 2 repeats the library override. [platform-publication-build.R](../../tests/platform-publication-build.R) line 24 requires the developer's TinyCC distribution. Runtime integrity checks should use the configured native manifest/Python; actual rebuild checks need a separate explicit compiler input and owned output. Do not make every installed-runtime check require a compiler. The connected smoke already demonstrated why a fresh checkout with different line-ending bytes needs its own source-specific native build. [Publication readiness](../../tests/platform-publication-readiness.R) already accepts `BROHN_PUBLICATION_NATIVE_MANIFEST`; configure that existing override rather than treating its fallback path as an unavoidable failure.

3. **Interchange: reusable designs before optional scientific streams.** [platform-task-portability.R](../../tests/platform-task-portability.R) line 4 overrides the R library. [platform-interchange.R](../../tests/platform-interchange.R) line 22 requires the acquisition Python profile. [platform-stream-curation.R](../../tests/platform-stream-curation.R) generates original inputs with general Python and performs actual EEG analysis, so it also needs the methods profile. Declare `BROHN_PYTHON`, `BROHN_PYTHON_ACQUISITION` and `BROHN_PYTHON_METHODS` explicitly as applicable; [platform-jobs.R](../../R/platform-jobs.R) maps interchange to acquisition. Offer a core ZIP/design-sharing subset separately from acquisition/EEG integration, with neither silently skipped nor presented as equivalent coverage.

## Bounded implementation and proof

The integration owner should add the configuration wrapper/catalog prerequisites first; test owners should then remove only their developer-path dependencies. Preserve reference package/version/source checks, actual worker tests and existing arithmetic expectations. Record missing prerequisites explicitly before execution. Retain new stores, native builds and all receipts outside Git, with source/configuration hashes and exact owned-process cleanup.

Qualify each selected group from an arbitrary-directory fresh clone with explicit existing runtimes and a new evidence root. This is source/environment portability, not a clean-OS installation claim. Keep the final integrated connected smoke as the immediate priority; broad catalog execution follows these dependency changes rather than preceding them.
