# Results and saved-review history

25 September 2026. This extends the shared researcher experience for reports,
original-container media and preserved linked signals. It does not add a new
scientific score or infer alignment between separate recordings.

## Report flow

The in-app report uses three native, keyboard-accessible sections: Results,
Explore and Evidence. Section IDs are report-specific; headings label each
region and links retain usable focus targets. Explorer controls remain mounted
so their Shiny bindings and saved states survive navigation. The primary HTML
download stays at the top; other exports and provenance belong in Evidence.

GNAT's leading cards use its saved eligible target/deadline outcomes. Complete
study context and scoring evidence remain available in a disclosure. Audio
shows up to eight saved features in original order, with units and exact
recording/segment/channel identity. Availability requires one matching computed
recording and a finite saved value; it never pools recordings or infers emotion
from acoustics. Full numerical tables remain available. The shared metadata
paragraph moves to Evidence so long saved report titles leave room for results
on a phone. The default standalone report content and export functions retain
their prior behavior.

## History and restoration

History uses a bounded metadata projection, pages of 20, date/id keysets and an
immutable entity-version watermark. It reads eligible current heads within the
snapshot. Later or backdated additions and later head revisions wait for Show
latest; current permission can remove entries. Totals describe currently
accessible saved views, not an immutable count of all historical revisions.
Metadata paging is separate from full source validation and creates no jobs.

Original media inventory lookup filters the complete matching history before
choosing the latest inventory. It therefore does not depend on the first page.
The existing original-media reader and native source/download guards remain
the authority for opening an exact saved reference.

Linked restoration applies a token tied to the saved import and channels and
waits for client acknowledgement before completing. Independently arriving
imports preserve an existing valid draft. Opening another saved view restores
its original import, track IDs, exact decimal window/cursor text, rationale,
confirmation and numerical row offset. A real dataset-context change resets
the draft deliberately. Current source authority is checked again for opening
and export; an old view never silently targets a newer import.

## Qualification boundaries and next work

Separate acceptance records retain component, actual browser, independent
source/export and restart evidence, with explicit source phases and failed
attempts. The linked paging corpus includes labelled synthetic metadata rows;
the media corpus includes 42 genuine supervised cursor preparations. Neither
implies physical synchronization accuracy or broader scientific validity.

Functional navigation is qualified for the retained fixtures. Source opening
still shows measured multi-second delays, including 17–18-second media reopen
and complete GNAT source/plot preparation around 18 seconds. Profile repeated
authority resolution and hashing, preserve the existing native guards and
fresh project checks, and improve progress feedback. Requalify the affected
actual route after a performance change. Large-catalog/concurrent workload
qualification remains open.

Reviewed alignment across separate recordings follows
[its own clock contract](REVIEWED-CLOCK-ALIGNMENT.md). Prepared arithmetic,
source inspection, event paging, map versioning and export components are not
an enabled researcher journey until supervised publication, selection UI and
complete review/export/restart acceptance are connected.
