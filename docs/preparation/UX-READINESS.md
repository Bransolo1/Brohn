# UX readiness for the next implementation programme

Build a premium research studio that lets a first-time researcher finish a defensible visual-design study and lets a commercial team reuse and inspect the same work without rebuilding it in spreadsheets.

Prepared 8 September 2026. This is a separate preparation review, not an implementation update. It applies the innovation-first-product-psychology skill to the current checkpoint and the directly relevant archived UX, questionnaire and architecture contracts. No participant testing, accessibility audit, device qualification or new competitor verification was performed. Acceptance targets below are proposed unless already stated in the archive; none are reported results.

The product's psychological promise is earned independence: “I can prepare, run, recover and explain this study.” The strongest differentiation is a coherent system of versioned recipes, low-effort automation, correct response/event linkage, recoverable decisions and understandable evidence. A polished builder is easy to copy; accumulated qualified recipes, reference fixtures, correction histories and reproducible outputs are harder to reproduce.

## What the existing plan already gets right

The archive preserves eye tracking, EEG, EDA, RT, physical push/pull AAT, named BIAT variants, questionnaires, webcam gaze/facial observations and automated AOIs. It already specifies progressive disclosure, immutable versions, explicit questionnaire referents, separate signal-validity masks, and method-specific control/practice/baseline requirements. These should be refined in their existing epics, not rebuilt as parallel subsystems.

The delivery guide is substantially narrower than that archive. The completed work is a useful local R/Shiny technical foundation, including portable saves, manual rectangular AOIs, prepared-interval arithmetic and protocol snapshots. Its current calculation is `aoi-valid-gaze-time-share/0.1.0-draft`; it is not a qualified raw-gaze preprocessing or inferential recipe. Sprint 1's human, hardware and scientific gates remain open. The following findings concern missing delivery acceptance or sequencing, even where the archive already specifies the intended feature.

## First complete flagship journey

Use “Compare two package or creative designs” as the first completed vertical journey. One participant sees both images, with declared A/B identities, appropriate control rationale, persistent AB/BA allocation, a predeclared primary AOI outcome and a liking item referring to each exact exposure. This is the approachable front door to the full multimodal product.

1. **Understand:** Open the fictional sample, inspect an explained result, then create an independent study from the recipe. Sample results never count as collected observations.
2. **Prepare:** Add two images and semantic targets; accept or inspect the recipe's design, collection plan, order, phases, quality policy and analysis. Preview the actual participant sequence and freeze a protocol revision.
3. **Obtain observations:** Initially use one explicitly supported, independently checked eye-data export with its event/exposure and liking records. Import, mapping and event joins are part of the product journey. A separate participant preview exercises instructions and responses; it does not establish physical timing or device readiness.
4. **Prepare data automatically:** Execute the named preprocessing/QC and AOI pipeline. Offer content-derived static AOI proposals with a visible review state. Preserve manual/numeric editing as an equivalent correction route and comparison baseline. Show only actual exceptions, including one deliberately seeded recoverable problem in verification.
5. **Finish and explain:** Finalize the declared collection, produce the prespecified comparison and separate liking outcome, explain sample loss and uncertainty, then export and independently reproduce the report. Preserve the prior snapshot when reopening or amending the study.
6. **Repeat:** Reopen the study, inspect its frozen result and create the next study from the same pinned recipe. A tutor or commercial reviewer can understand the export without this application's internal vocabulary.

The import route completes an analysis workflow once its importer, method and usability checks pass. Completion of actual study collection additionally requires the participant runner and one named eye device/configuration to pass physical execution and timing qualification. The full launch destination remains eye+EEG+EDA collection, separate qualified RT/AAT/BIAT blocks, integrated questionnaire flow and one evidence-linked report. Webcam collection has its own calibration, capability and model-evidence matrix. These are later evidence gates, not capabilities implied by the initial journey or a single large coding pass.

## Eight concrete readiness corrections

### 1. Make complete-task learning precede module expansion

**Observation:** The delivery guide places undergraduate/commercial testing in its last item, despite the archive requiring formative work during foundation. Current browser checks verify implemented controls, not whether operators can finish and explain a study.

**Mechanism:** Consistent small successes build competence; accumulating disconnected modules leaves the novice responsible for integration.

**Build response:** Make the first journey and one recovery path the organizing acceptance slice. Run formative walkthroughs while the runner/import/report path is still changeable. Include novices, commercial researchers and accessibility participants across the programme. Keep the full modality contracts in parallel, with explicit integration destinations.

**Proof:** First formative round records every attempted task, unaided completion, assistance, errors and interpretation. Retain the archive's initial 80% sample-completion target as a directional formative target, with raw counts and uncertainty; do not call a small round qualification. No further broad authoring expansion until critical findings have a concrete repair or documented test plan.

### 2. Turn “low click” into an instrumented whole journey

**Observation:** Action budgets exist in the archive, but full interaction instrumentation remains open. Repeated navigation, upload dialogs and confirmations can consume the budget without appearing in component tests.

**Mechanism:** Decision fatigue comes from unexplained choices as well as clicks. Reliable defaults and a visible next action support agency without requiring scientific configuration.

**Build response:** Add workflow/mode-aware action and decision counting before further shell expansion. Record manual file-dialog actions in observation when the browser cannot capture them. Keep one primary next step, inspectable recipe defaults and a route to the same advanced specification.

**Proof:** Verify the archived budgets end to end: prepared sample ≤5 activations, zero scientific decisions and ≤10 minutes; prepared real-study authoring ≤4 substantive design decisions and ≤12 activations; next participant ≤4 software activations. Report typing, installation, sensor fitting, consent, calibration and exception work separately. Pair speed with correct explanation of the primary outcome and its limits.

### 3. Bring the questionnaire execution kernel forward

**Observation:** The delivery guide groups richer questionnaires and flow late. The archive correctly places exposure-linked liking in the earliest foundation; a saved question definition alone does not prove rendered questions, accepted answers or repeated exposure joins.

**Mechanism:** “Ask about this image” should preserve the user's intent automatically. Manual joining weakens confidence and defeats the integrated platform promise.

**Build response:** Deliver one complete liking renderer, typed missing states, question visibility/submission events, exposure referents and response history alongside the participant preview and event-binding increment. Use the shared typed flow model from the outset; expand question types, branching/piping and reusable instruments through named coverage sets. Keep EEG/EDA response periods distinct from passive viewing.

**Proof:** Fixture traces for AB/BA, repeated exposures, omitted answers, reload and retry all join to the intended exposure and question revision exactly once. An untouched scale stays missing rather than becoming zero. Branch changes preserve answer history and apply the declared eligibility policy. Novices can explain what an item refers to without inspecting IDs. “Qualtrics-quality” remains a target until the selected type/logic set passes runtime and user tests.

### 4. Freeze method phases before freezing executable plans

**Observation:** Control designation and sequence preview are delivered, while baseline, practice, attention checks and method-specific counterbalancing remain future work. The generic control label does not supply these semantics.

**Mechanism:** A smoothly generated plan can encourage users to assume that similarly named stages are scientifically interchangeable.

**Build response:** Give the initial recipe explicit phase roles and inclusion rules now. Show control/test, fixation cue, practice, baseline/rest, passive view and rating as distinct concepts wherever the recipe uses them. Validate required phases during compilation. Each future EEG/EDA/AAT/BIAT recipe supplies its own timing, mappings, practice and scoring policy; unused phases stay absent rather than requiring generic configuration.

**Proof:** Golden plan fixtures preserve stimulus identity under reversed order, distinguish planned from achieved balance, exclude practice from scored trials, and keep rating gaze out of stimulus AOIs. Relevant edits invalidate only dependent preview/qualification evidence. A novice can identify the experimental comparison and distinguish control from baseline in the generated timeline.

### 5. Design session recovery and study completion with the runner

**Observation:** Preview and persistent allocation are next; current delivery summaries do not make collection finalization and the repeated-participant recovery loop part of the same acceptance boundary. The archived UX review defers finalization semantics too far toward release qualification.

**Mechanism:** Clear saved progress and local repair preserve confidence after interruption. Ambiguous “finished” messages can make one participant's end look like an entire study's completion.

**Build response:** Define separate participant completion, recording persistence, analysis eligibility and collection-finalized states with the runner. Add fresh-session creation, checkpoint/attempt lineage, explicit interruption policy and scoped readiness evidence. Tie finalization to the collection plan and automatic frozen analysis; expose reopen as a versioned continuation.

**Proof:** Two sequential participants share no answers. Duplicate start/retry requests create no duplicate allocation or accepted answer. Reload during a trial reports the actual saved boundary and gap. Finalization with unresolved data states explains what remains; reopening preserves the previous report. Human operators recover from a seeded interruption unaided in the first journey study.

### 6. Make accessibility a feature exit condition

**Observation:** Keyboard AOI checks exist, but full assistive-technology qualification is open and the delivery guide lists accessibility late. New flow editors and signal plots will multiply repair work if their equivalents are postponed.

**Mechanism:** Predictable focus, explicit labels and alternative controls enable mastery and efficient expert operation, as well as access.

**Build response:** Require semantic controls, focus restoration, linked errors, status announcements and equivalent non-dragging actions when each surface is introduced. Build text/table equivalents for results and signal inspection. Specify participant accommodations separately from measurement equivalence; preserve input/display configuration in timed-task data.

**Proof:** On a declared browser/keyboard/screen-reader matrix, complete authoring, AOI edit, participant question/error recovery and result tracing without pointer dependence or silent value changes. Exercise zoom/reflow and dynamic updates. Automated checks supplement observed task testing; WCAG conformance is not inferred from scanner scores or screenshots.

### 7. Finish with an understandable, reusable deliverable

**Observation:** Reproduction and evidence manifests are strong in the archive, but the current result is a bounded draft and neither recipient comprehension nor repeated commercial/course use is demonstrated.

**Mechanism:** A finished report is the moment confidence should become portable: the researcher can explain the work to a tutor or decision maker and start again from what worked.

**Build response:** Pair each outcome with its definition, valid denominator, exclusions, uncertainty and one-step provenance. Present attention, liking and physiology as separate outcomes before any qualified association model. Provide a clear completion state, accessible report preview, reproducible bundle and pinned recipe reuse; defer live sharing infrastructure until its deployment scope is needed.

**Proof:** Every card resolves to its frozen inputs; stale results cannot silently replace a final snapshot. Independent reproduction agrees with the exported result. In a blinded recipient task, reviewers identify the compared conditions, outcome meaning, valid sample and one limitation. A returning operator creates a second independent study without mutating the original.

### 8. Give automation a measured operator-effort contract

**Observation:** Automated AOIs and preprocessing are central in the brief and well specified in the archive, but the current application provides manual AOIs and prepared-data arithmetic. Sequencing automation only as another later module would underdeliver the premium experience.

**Mechanism:** Automation earns trust when it visibly completes useful work and makes uncertain exceptions easy to correct. High acceptance rates alone can reflect over-trust.

**Build response:** Include static AOI proposals and automatic preparation in the first complete journey once appropriate fixtures exist. Keep proposed/accepted states explicit, group exceptions by required decision, preview bulk impact, preserve undo and measure correction effort. Graduate to DOM/video tracking and broader modality automation using their own benchmark gates.

**Proof:** On a held-out permitted stimulus/recording set, compare end-to-end operator minutes and downstream metric agreement against the manual baseline at the same declared quality target. Include confident but incorrect proposals and verify discovery/recovery. Set numerical scientific tolerances in the method specification before evaluation; report failed automation and review time in the total, not only clean-case speed.

## Build and claim boundaries

| Stage | Concrete destination | Evidence required |
|---|---|---|
| Build now | Frozen event/flow references, linked liking, persistent allocation, participant preview, accessible controls, collection lifecycle, action instrumentation and report comprehension prototype | Executed contract/recovery fixtures and inspectable UI paths; formative findings recorded honestly |
| Build instrumented | Qualified import-to-report eye journey, static AOI proposals, automatic preparation, named initial EEG/EDA pipelines and RT/AAT/BIAT task packs | Independent references, bounded method/type coverage, operator-effort benchmarks and representative user studies |
| Graduate later | Live reference rig, qualified webcam configurations, richer questionnaire suite, dynamic AOIs and commercial release | Physical acquisition/timing evidence, method and model qualification, accessibility/user evidence, installation/recovery gates and named supported matrix |

Technical completion means that the declared software path and failure cases work and reproduce. Scientific qualification means independent method/reference and configuration evidence supports its specified outputs. User qualification means intended operators can complete, recover and correctly interpret the workflow under observed conditions. Hardware/browser timing and webcam model qualification add separate evidence. None substitutes for another.

Claims available now are limited to the technical capabilities recorded in `STATUS.md`. Usability or speed claims become available after observed studies with their conditions reported. Broader decision-quality, device-generalization or facial/attention construct claims require the corresponding independent and longitudinal evidence. Strong visual design can be built immediately while those claims advance honestly.
