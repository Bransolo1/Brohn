## Larger implementation waves

| Wave | Integrated outcome and exit evidence |
| --- | --- |
| 1 | Protocol-bound sessions/events, realized presentation IDs, multimodal run/channel/object/clock manifests and schema migrations. R/browser fixtures must preserve repeated exposures, original timestamps, resets and gaps. |
| 2 | Preloaded participant runner, persisted assignment/journal, committed liking, typed question/branch foundation and truthful collection states. Prove reload/disconnect/retry and response-linkage behavior. |
| 3 | First complete eye-study workflow: one specified vendor import, coordinate/QC/preprocessing recipe, durable jobs, linked liking and understandable reproducible report. Add static AOI proposals, correction/undo and held-out reference benchmarks alongside the manual baseline. |
| 4 | Integrate the broader neural/fNIRS, peripheral physiology, implicit/cognitive, questionnaire, webcam/audio and choice packs from the capability register. Each consumes shared identity/phase/job contracts and retains independent method/QC fixtures and its declared implementation tier. |
| 5 | One supported live multimodal rig: named devices/OS/SDKs, preflight, sidecar and clock diagnostics. Physical onset/sync and failure recovery must be measured on the actual configuration. |
| 6 | Dynamic AOIs, reviewed inference/multimodal recipes, historical results, reproducibility packaging, backup/restore and open-source release. Publish a measured support matrix. |

Start rig/SDK feasibility and remaining BIAT/AAT execution/reference work during Wave 1.
Novice testing, accessibility and operator-effort/comprehension measures belong in
every wave. Static AOI automation belongs in the first complete eye-study journey;
video/DOM AOIs have later benchmarks. Questionnaires and control/baseline/practice/
check semantics must enter the execution foundation, not a late UI-only extension.

Independent packs can run in parallel after shared contracts stabilize. Integrate
and checkpoint each wave. Software, scientific, physical timing and user success
remain separate gates. See [build preparation](preparation/BUILD-READINESS.md),
[UX review](preparation/UX-READINESS.md), [architecture review](preparation/ARCHITECTURE-READINESS.md)
and [tools](preparation/TOOLING.md).

Use the archived roadmap for breadth and sequence, never as a claim that a
complete commercial product fits into the first twelve provisional sprints.
Control-design requirements are tracked in methods/CONTROL-DESIGN.md; a generic
control label or order preview does not satisfy the later method-specific gates.
