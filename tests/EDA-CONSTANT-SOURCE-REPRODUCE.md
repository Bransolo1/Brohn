# Exact-constant EDA source and reader checks

These tests qualify a bounded version boundary. They do not establish general
scientific response validity, physical-device qualification or a complete
platform release. Keep the original 1.0 outputs unchanged.

Use the configured Brohn R library and native publication guard. The same R,
Python and scientific-runtime prerequisites apply as in the installation guide.
The test checkout must contain the joined implementation: preparation 0.2,
continuous review 1.1 and their exact producer/reader dependencies. No test
downloads or installs a runtime. All output directories must be fresh.

```text
Rscript --vanilla tests/eda-constant-source-contract.R REPO COMPONENT_OUTPUTS OLD_EDA_ORIGINALS FRESH_OUTPUT
Rscript --vanilla tests/eda-constant-model-contract.R REPO COMPONENT_OUTPUTS FRESH_OUTPUT
Rscript --vanilla tests/eda-constant-reader-contract.R REPO PYTHON_READER_OUTPUTS FRESH_OUTPUT
Rscript --vanilla tests/eda-constant-history.R REPO ORIGINAL_STANDALONE_REVIEW FRESH_OUTPUT
```

`COMPONENT_OUTPUTS` is the original scientific component test output, with
`constant-1` through `constant-6` and the declared eligibility/segmentation/legacy
cases containing `result.json` and their complete artifact files. They must be
generated by the producer tests, not manufactured saved reports. The first test
also consumes unchanged `event-report.json` and `continuous-report.json` from
the generated old EDA original corpus. It checks full original vocabularies,
version refusal and feature/null/denominator conservation without rescoring.

The model test constructs a clearly labelled structural model from real
component features and table headers. This is useful for malformed-field refusal;
it is not evidence of Python execution or native publication.

`PYTHON_READER_OUTPUTS` contains the six same named cases from the pure reader
test. Each supplies `request.json`, `model.json`, `prepared-request.json`,
`evidence.json` and `catalog.json`. The R test validates the actual returned
model, cross-language typed hash, catalog and coordinate-only support. Synthetic
report wrappers in that fixture do not establish stored-source authority.

`ORIGINAL_STANDALONE_REVIEW` is a closed, genuinely published recipe 1.0 review
fixture with `FREEZE.json` and `workspace/`. The test copies the workspace before
opening it. It holds original sources, retained documents and complete CSVs with
the native guard, verifies old code identity is different while the old read
remains valid, and confirms current producer revocation still refuses. That
revocation probe uses a rolled-back transaction in the copy. Jobs, entity
versions, object metadata and the supplied original inventory remain unchanged.
No services or browser are launched.

Every test writes `results.json` with individual checks, scope and any error.
Preserve failed attempts. Passing these tests does not replace joined native
scientific/preparation/publication, accessible UI, complete report export or
historical package gates.
